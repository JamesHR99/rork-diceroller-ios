# DiceRoller enemy art — transparent edition

Status: Background transparency complete. Original four-keyframe animations remain available for production review.

All 15 enemies beyond Straw Effigy are included. The three serpent lords in the current code are Sekhen, Nehebkau and Apep; Apep is not a fourth additional lord. Two extra Apep sheets provide Coils and Maw action variants.

## Contents

- 17 cleaned sprite sheets, 1254 × 1254 RGBA PNG with real transparency.
- 17 character-art exports, using each sheet's first idle frame.
- 272 extracted PNG frames, 314 × 314 (four frames in each of four rows).
- 68 animated lossless WebP previews, four per sheet.
- `index.html`: open after unzipping to switch actions across the whole roster.
- `manifest.json`: character IDs, frame paths, exact crop boxes, timing and phase IDs.
- A complete generation prompt in each enemy folder.

## Important production limits

The checkerboard backgrounds have been removed from all 17 sheets, 272 extracted frames, 17 character exports and 68 animated WebP previews. PNGs use RGBA; the WebPs retain alpha in every frame. Empty areas have alpha zero. Pale enclosed details are protected, edge pixels are decontaminated, and the Ash Jackal's flattened smoke has been selectively descreened and given reconstructed soft alpha. Transparent RGB pixels are zeroed to prevent hidden matte colours from bleeding during texture filtering.

Open `index.html` after extracting the ZIP. Switch the preview background between dark, light and a CSS checkerboard to inspect transparency. The checkerboard option is generated by the page and is not embedded in the artwork. The original archive is not included in this cleaned pack.

The artwork itself has not been regenerated. Previously flattened effects cannot recover their original alpha exactly; the supplied soft alpha is a reconstructed matte.

These are four-keyframe animation drafts. They include generated pose changes, not merely whole-image sliding, but proportions, anchors and effects still need production cleanup. Some long attack effects approach or cross the implied cell boundary. Images were requested at 2048 × 2048 but the generator returned 1254 × 1254; exports preserve the returned resolution rather than claiming upscaled detail. Fixed frame crops overlap by up to one source pixel because 1254 is not divisible by four. Character exports reuse idle frame 0; they are not separate high-resolution portrait commissions.

The current GitHub tree contains the painted hero reference and enemy definitions but lacks the earlier enemy base drawings listed in the inventory. These designs follow the current source descriptions and the available hero style reference; they cannot be verified as exact redraws of those unavailable originals. The extra Apep phase sheets preserve the head design, but are pose variants rather than fully different encounter compositions.

## Motion and runtime mapping

Rows from top to bottom: idle, attack, reactive block impact, sustained defend. Columns play left to right. Attack: anticipation, action, impact/follow, recovery. `block` reacts to a hit; `defend` enters a protective stance. Defend should hold frame 2 (zero-based) after entry; some final drawings return toward idle. Review WebPs repeat to make inspection easy, while combat attack and block should run once.

The game currently has a `.block` pose but no separate `.defend` pose. A future integration can play block on impact and hold defend while guarding. `SpriteClipLibrary` currently resolves only archer sheets and must be extended before these enemy clips can run. Keep enemy IDs unique for Silt Colossus, Bronze Effigy and Boneplate Devourer instead of retaining their shared-art fallback aliases. Normalise `_herald`, `_armoured` and `_pack` suffixes when choosing enemy art. Apep stage IDs are `apep_head`, `apep_coils`, and `apep_maw`; stage-based art selection needs explicit integration. No source code, commits, branches or pull requests were changed during this task.
